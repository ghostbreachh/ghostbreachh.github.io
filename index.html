ILLUSTRATIVE SECURITY FINDINGTenant isolation

1. Explain the finding

An authenticated request can access a record belonging to a different tenant because the lookup omits tenant ownership.

CONTEXT
Authenticated account in tenant AThe caller is signed in; the record belongs to tenant B.
↓
CAUSE
Lookup uses only the record IDThe data query lacks the authenticated tenant boundary.
↓
IMPACT
Unauthorized cross-tenant readRecord the exposed fields and affected scope before assigning severity.

2. Connect the fix to the cause

Illustrative handler fragment. Trusted authentication middleware supplies the tenant; application-specific role and object permissions still apply.

// Scope the record to the authenticated tenant.
const record = await db.records.findFirst({
  where: {
    id: req.params.id,
    tenantId: req.auth.tenantId
  }
});
if (!record) return res.sendStatus(404);
return res.json(toPublicRecord(record));

Retest: allowed tenant, different tenant, unauthenticated caller, and every route or method that exposes the record.

2. Native C firmware & offline flashing

The reference package pairs ESP-IDF C source with Windows/macOS/Linux flashing instructions and a bill of materials.

#!/usr/bin/env bash
# Reference ESP32 build; legacy esptool 4.x syntax
set -euo pipefail
: "${PORT:?Set PORT to the connected ESP32 serial port}"
esptool.py --chip esp32 --port "$PORT" --baud 921600 write_flash -z \
  0x1000 bootloader.bin \
  0x8000 partition-table.bin \
  0x10000 stadium_blueprint_prod.bin

Offsets shown are for this ESP32 reference layout. Match the build’s generated flash arguments when using other images or boards.
